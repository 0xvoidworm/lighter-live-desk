# Perbaikan lokal Lighter Live Desk

Lanjutan audit 30 September, diverifikasi 1 Oktober 2026 WIB. Baseline Git
`cbc3f54`; perubahan berada di working tree lokal, belum di-commit/push.

Dashboard: <http://lighter.localhost:8765>, alternatif
<http://127.0.0.1:8765>. Engine/API dijalankan sebagai layanan user dalam mode
`observe`, dengan `allow_live_orders=false` dan account index belum diisi.
Autostart tidak diaktifkan. DNS laptop/router tidak diganti.

## DNS dan feed yang diperbaiki

Resolver lokal router `192.168.1.1` memberi CNAME `trust.tunaslink.net.id` dan
alamat `103.133.62.251` untuk kedua host Binance. REST gagal sebelum TLS. Uji
DNS over HTTPS Cloudflare/Google menghasilkan alamat lain dan REST resmi HTTP
200 dengan TLS diverifikasi. Karena itu konfigurasi lokal memilih `doh`.
Temuan ini menjelaskan perbedaan jalur koneksi yang diuji; tidak mengidentifikasi
pihak atau kebijakan yang menyebabkan jawaban DNS lokal tersebut.

`src/lldesk/network.py` menerapkan resolver khusus feed publik Binance, cache
sesuai TTL sampai 60 detik, penolakan alamat nonpublik, timeout, serta fallback
Cloudflare ke Google. Koneksi memakai hostname resmi dan pemeriksaan sertifikat
TLS biasa. Lighter, resolver sistem, DNS router, dan `/etc/hosts` tidak diubah.
Pilihan `system` tetap tersedia untuk jaringan yang memberi jawaban benar.
Format DNS mengikuti [dokumentasi Cloudflare](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-https/make-api-requests/dns-json/).

REST dan kedua WebSocket Binance memakai transport aiohttp yang sudah ada di
lockfile. Rute depth/bookTicker `/public` dan aggTrade `/market` dipertahankan,
sesuai [panduan migrasi Binance](https://www.binance.com/en-TR/support/announcement/detail/ebf9b0aa9eca4ff3804eef6fb09ba32a).

Uji feed langsung membuka bug tambahan pada urutan depth. Setelah bridge,
update ID `U` bisa melompat meskipun `pu` cocok dengan `u` sebelumnya. Pemeriksaan
U setelah bridge dihapus; gap `pu` tetap menginvalidasi book dan memicu resync,
sesuai [prosedur order book Futures resmi](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/websocket-market-streams/How-to-manage-a-local-order-book-correctly).

Probe publik sesudah perbaikan menerima 1 snapshot Binance, 17 depth update,
230 bookTicker, 6 aggTrade, dan 30 order_book Lighter; bridge berhasil dan gap
nol. Tidak ada signer/account adapter dalam probe itu.

## Sembilan regresi audit

Harness audit lama disalin ke `tests/test_audit_regressions.py`. Mock disesuaikan
dengan field margin/account mode dan metode riwayat trade pada kontrak terbaru.
Fixture posisi milik engine diberi fill yang sesuai; assertion keselamatan tetap
dipertahankan. Sebelum patch produksi, kesembilan assertion gagal tanpa error
setup pada sumber terbaru. Sesudah patch seluruhnya lulus.

| Temuan | Perubahan |
| --- | --- |
| Exit macet pada `canceled-*` | Satu normalisasi status terminal untuk jurnal, exit, dan cleanup stop; jumlah attempt persisten tidak direset saat menemukan posisi setelah restart. |
| Equity > US$50 melewati proteksi | Batas sumber dana memakai gross inflow persisten. Kenaikan equity tidak mengabort rekonsiliasi/proteksi posisi. Guard aset atau notional menghentikan entry tanpa early exception. |
| Stop tidak mencakup ukuran terbaru | Verifikasi market, sisi, quantity, trigger, jenis stop, dan reduce-only. Hilangnya cakupan stop yang sebelumnya terkonfirmasi meminta close; ketidakpastian tetap tidak di-retry secara buta. |
| Entry terkirim sesudah cancel saat menunggu signer | Epoch pembatalan dibawa sejak penjadwalan, diperiksa di dalam lock tepat sebelum signer. Intent belum terkirim dapat menjadi CANCELED lokal; transmisi yang mungkin terjadi tetap direkonsiliasi. |
| Poll gagal menghabiskan slot exit | Entry dan polling dibatasi 40 slot; exit/cancel dapat memakai sampai 55. Claim transaksi dilakukan setelah memperoleh lock. |
| Poll akun menahan heartbeat/commands | Satu task polling dengan lock rekonsiliasi dan deadline 8 detik; loop foreground tetap memproses command dan heartbeat. Waktu attempt disimpan meskipun gagal, dengan interval polling 10 detik. |
| Timestamp snapshot dibuat sesudah history | `received_at` dicatat segera saat respons equity diterima. History lambat tidak menyegarkan equity lama. |
| Entry rejected mengklaim posisi manual | Ownership memerlukan net quantity fill lokal yang cocok dengan snapshot, bukan keberadaan intent. Snapshot dipublikasikan setelah bukti ownership tersedia. |
| Probe lebih besar dari minimum legal | Mode sizing minimum membulatkan minimum base/quote ke step sambil tetap tunduk pada cap risiko, notional, equity, dan cadangan exit. |

Status order dan field stop mengacu pada [referensi WebSocket Lighter](https://apidocs.lighter.xyz/docs/websocket-reference);
budget lokal tetap di bawah [batas Standard yang menjadi acuan proyek](https://apidocs.lighter.xyz/docs/rate-limits).

## Throughput dan dashboard

Pemeriksaan runtime pertama menunjukkan backlog 1.235 event dan usia quote
Binance 7.389 ms / Lighter 15.176 ms. Penyebab yang diperbaiki adalah status
SQLite FULL yang ditulis pada setiap event. Uji burst sebelum patch mencatat
2.000 penulisan untuk 2.000 event dan gagal terhadap batas yang ditetapkan.

Engine sekarang memproses maksimum 256 event atau 10 ms per batch, menjaga
urutan setiap event, lalu memproses command dan pengelolaan posisi. Heartbeat
ditulis maksimal empat kali per detik. Book basi kini diberi `valid=false` pada
status/UI meskipun struktur book masih lengkap.

API menerima host/origin `lighter.localhost` hanya pada port lokal yang
ditentukan. Bind tetap `127.0.0.1`; foreign origin dan request tanpa CSRF ditolak.
UI mengambil CSRF baru saat pengguna meminta command, sehingga restart API tidak
mengharuskan reload halaman. Tidak ada pengiriman ulang POST otomatis.
Kontrol Start/Probe dinonaktifkan saat guard status tidak mengizinkannya.

Sesudah patch, 25 sampel sekitar 25 detik menunjukkan seluruh heartbeat dan
stream tersambung, backlog/gap nol, umur maksimal quote Binance 89 ms dan Lighter
282 ms. Pemeriksaan browser berikutnya menunjukkan umur 15 ms dan 2 ms, tanpa
error/warning console. Ini bukti observasi lokal pada jendela uji, bukan jaminan
latency atau stabilitas pada semua kondisi jaringan.

Pemeriksaan akhir **1 Oktober 00:18:50 WIB** menunjukkan warm-up 600 detik selesai
dan state `READY` dalam **observe**, entry tetap berhenti, akun belum tersambung.
Age Binance/Lighter 53/36 ms; backlog, gap dan reconnect nol. Engine PID 83706
aktif sejak 00:08:39, API PID 82658 sejak 00:02:19; NRestarts otomatis keduanya
nol. Hasil ini tidak mengubah batas integrasi akun nyata di bawah.

## Validasi dan batas

55 tes lulus. Ruff check dan format, mypy 12 modul, TypeScript/Vite build,
config/SQLite check, dan `git diff --check` lulus. Tiga warning deprecation dari
dependency yang dipin masih ada; dependency/lockfile tidak diganti.

Python/TypeScript dipertahankan karena proyek dan SDK signer resmi memakai
toolchain tersebut. Tidak ada pembacaan kredensial, API akun nyata, pendanaan,
order mainnet, perubahan Binance Desk, atau konfigurasi DNS global. API dan
engine tetap terpisah, single-instance lock tetap digunakan.

Warm-up 600 detik tidak dilonggarkan. Account tier/margin, kelengkapan ledger,
proteksi stop dan fill mainnet tetap belum diuji pada akun nyata. Hasil ini
menyatakan aplikasi/feed berjalan lokal dalam observe, bukan kesiapan trading
uang nyata atau profitabilitas strategi.

## Menjalankan kembali dan rollback

```bash
cd ~/lighter-live-desk
systemctl --user start lighter-live-desk-engine.service lighter-live-desk-api.service
```

Jangan menjalankan `dev.sh` bersamaan dengan layanan ini. Untuk dev runner,
hentikan layanan ketika mode observe dan tidak ada sesi/posisi aktif. Pemasangan
dependency mengikuti `uv sync --frozen --extra dev --python 3.12` dan `npm ci`.

Untuk kembali ke DNS laptop, ubah hanya `binance_dns_mode` menjadi `system`, lalu
restart engine ketika sesi tidak aktif. Jawaban router yang terlihat pada uji
ini masih membuat koneksi Binance gagal. Backup konfigurasi sebelum perubahan:
`/home/yuri/Workspace/outputs/lighter-live-desk-fix-20260930/config-before.json`.
Jangan menyalin backup ke konfigurasi bila ada pengaturan akun baru sesudahnya.

Untuk rollback kode, gunakan diff/baseline `cbc3f54` dengan meninjau perubahan
pengguna yang mungkin datang sesudah tugas ini; jangan reset working tree secara
menyeluruh. Hentikan layanan sebelum mengganti kode dan verifikasi mode/config
sebelum memulai kembali.
