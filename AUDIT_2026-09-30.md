# Audit hambatan uji live — 2026-09-30

## Bukti koneksi di lingkungan engine

Engine development yang aktif adalah PID 64308, user `yuri`, `mode=observe`, dan memegang `state/engine.lock`. Network namespace-nya `net:[4026531833]`, sama dengan shell pemeriksaan. Tidak ada variabel proxy HTTP/HTTPS/ALL/NO pada environment proses engine atau manager systemd user. Unit engine terpasang dengan `WorkingDirectory=/home/yuri/lighter-live-desk`, `Environment=` kosong, dan `ExecStart` ke venv proyek. Diagnostik dijalankan melalui `systemd-run --user` pada manager yang sama. Unit engine tambahan sempat dicoba, ditolak oleh lock, lalu dihentikan; proses development yang sudah ada tetap berjalan.

Kesimpulan terbatas: jalur jaringan ke host Binance USD-M gagal sebelum TLS dan sebelum aplikasi dapat mengirim HTTP/WS. Jawaban DNS yang berbeda perlu ditinjau bersama konfigurasi router/penyedia jaringan, tetapi bukti belum cukup untuk menyebut pembatasan wilayah, blokir platform, atau kesalahan TLS. Tidak ada DNS, proxy, endpoint alternatif, atau rute jaringan yang diubah untuk melewati pembatasan. Gunakan dukungan router/ISP atau jaringan biasa yang memang berwenang mengakses layanan; bila akses tidak tersedia, mesin tetap observe dan tidak mengganti venue pembanding tanpa keputusan baru.

Pemeriksaan lanjutan setelah pengguna meminta mencoba API Binance Desk: kredensial proyek itu dikelola oleh KWallet dengan service `io.yuri.BinanceDesk` (`desktop-rs/src/vault.rs`), bukan bagian dari Lighter Live Desk. Isinya tidak dibaca, disalin, atau dipakai. Konektor publik Binance Desk (`desktop-rs/src/market.rs` dan README) mengambil candle REST dengan fallback DNS publik tersendiri; ia tidak menyediakan depth/trade WebSocket yang diperlukan strategi ini. Dari network namespace engine Lighter `net:[4026531833]`, tanpa proxy environment, `dig` kembali memberi CNAME `fapi.binance.com -> trust.tunaslink.net.id -> 103.133.62.251` dan `fstream` pernah memberi alamat yang sama; `getent` pada percobaan lain memberi `203.119.13.75/.76`. `nc` port 443 memberi `No route to host` atau `Connection refused`; Python `websockets.connect` ke rute resmi memberi `OSError errno=113` pada `/market` dan timeout pada `/public`. Dengan demikian API key tidak menyelesaikan kegagalan sebelum TLS/HTTP; fallback DNS dari proyek lain tidak diaktifkan di sini karena status pembatasan jaringan belum jelas.

Dokumentasi Binance yang diperiksa pada tanggal ini: [koneksi routed WS](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/websocket-market-streams/Connect), [pemetaan stream](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/websocket-market-streams/Important-WebSocket-Change-Notice), dan [bootstrap local order book](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/websocket-market-streams/How-to-manage-a-local-order-book-correctly). Kode lama mengirim `aggTrade` ke `/public`; sekarang bookTicker/depth memakai `/public`, aggTrade `/market`, dan kedua koneksi wajib sehat sebelum entry. Snapshot REST tetap `https://fapi.binance.com/fapi/v1/depth`. Perbaikan kode baru diverifikasi lewat fixture; koneksi Binance nyata masih terblokir.
